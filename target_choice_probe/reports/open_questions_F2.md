# Открытые вопросы Stage F2 (решения приняты консервативно, до результатов)

1. **Плацебо типа 1 не совсем «пустые».** Сдвиг реального признака на ≥ 60 суток внутри актива сохраняет устойчивые свойства
   актива (например, «этот коин всегда волатильнее»), а такие свойства реально связаны с будущей доходностью и особенно с
   волатильностью. Поэтому часть «ложных срабатываний» типа 1 — не чистый шум. По заданию P3 считается по всем плацебо
   (это строже); в `placebo.md` показаны отдельно тип 1 и тип 2 (шум AR(1) — чистый ноль).
2. **Ветка D, бутстреп.** Ранги признака и цели по пулу (время × актив) считаются один раз на окне; в бутстреп-повторах не
   пересчитываются. Пропущенное значение признака заменено нулём (средним по срезу) до ранжирования.
3. **Ветка X, T1/T3/T4 (и T5/T6) имеют одинаковый отбор**, так как ранговая IC не меняется при монотонном преобразовании цели
   внутри бара. Это не ошибка, а свойство постановки; различаются только коэффициенты модели.
4. **Вердикт, если P1–P4 проходит только T1.** Правило в задании говорит о разности с T1, а T1 сам с собой не сравнивается.
   Принято: «ЦЕЛЬ РЕКОМЕНДОВАНА (T1)», если T1 — единственная прошедшая цель; если прошла одна не-T1 цель, но интервал
   разности с T1 включает ноль, — «РАЗНИЦА НЕ ДОКАЗАНА».
5. **CCR** = (ценовая прибыль + фандинг) / издержки S1 за весь период.
6. **Фаза пересчёта** — глобальный номер бара, делящийся на h (одна и та же для всех целей и месяцев).
7. **Дрейф весов** внутри удержания не моделируется (веса постоянны до следующего пересчёта). Если открытия следующего бара
   нет (пропуск/делистинг), доходность бара считается нулём.
8. **OI и фандинг как признаки** — последнее значение строго внутри бара (метка < конца бара), чтобы не зависеть от того, к
   какому моменту API относит снимок.
9. **Регулятор волатильности** — множитель на актив: медиана прогноза по активам / прогноз актива, в [0,5; 2], без
   перенормировки валового объёма (средний множитель ≈ 1). Прогноз — модель T7 (HAR + признаки) того же горизонта.
10. **θ ветки D** выбирается по внешневыборочному Шарпу разработки (3 варианта на пару (цель, h)), поэтому цифры ветки D на
    разработке слегка оптимистичны; контроль от этого выбора свободен.
11. **Выбор α** — по MSE (Ridge) и log-loss (логистическая), а не по деньгам.
12. **RV** считается по ln(close/open) каждой часовой свечи.
13. **Если для T7 ничего не отобрано**, модель «с признаками» совпадает с HAR (Ridge на трёх регрессорах).
14. **Конец разработки.** Позиции, открытые на последнем баре разработки, не закрываются (стоимость выхода не начисляется) —
    влияние на итог на уровне одной сделки.
15. **A101:** V = оборот в USDT вместо объёма в штуках; сверка по вторичному источнику (см. `doc_check_F2.md`, п. 8).
16. **Фандинг в PnL:** выплата = ставка × вес (марк-цена ≈ последняя), расчёт на границе бара относится к бару, который
    держался до этой границы.
