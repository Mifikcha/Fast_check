# Stage 2 implementation plan (frozen 2026-10-05)

1. Preserve Stage 1 data and its CLI. A long experiment has an immutable experiment ID and initial manifest; every start or resume creates a fresh ordinary collector session. Increase long-run Parquet rotation to 15 minutes / bounded rows. Existing atomic parts remain the storage unit. Report interrupted sessions and inter-session downtime explicitly.
2. Freeze the 2026-09-12 Ridge@30s decision in `configs/confirmatory_ridge30.yaml`: source run and dataset hash, exact 79 features, median imputer, standard scaler, alpha 0.1, 0.5 bps signal threshold, validation-frozen quantile edges, original test IC. Refit coefficients only on the original development interval, never on Stage 2 days.
3. Build each completed UTC day from the recorded sessions. Reindex to a complete second grid; mark physical gaps and every invalid/resync/stale book second; apply ±60 s buffers. A row and its entire target interval must avoid those buffers. Export source and buffered intervals, per-day usable duration, and global reliability separately.
4. Write a longitudinal analyzer in small daily units. Confirmatory daily Ridge metrics, frozen deciles, every non-overlapping 30 s phase, day-level uncertainty and expanding evidence are primary. Additional horizons, OBI-only signals, group ablations, regimes, latency, costs and selectivity are explicitly exploratory. At 250/500 ms, raw book event replay supplies subsecond quotes/OBI; delayed execution uses the first valid state at or after the latency deadline, while stale OBI uses the last state at or before decision minus latency. Never infer subsecond Ridge features from the one-second table.
5. Add `collect --days --resume`, `status`, `daily`, `analyze-long`, `report-long`. Daily artifacts are immutable per date; the final analysis writes the required CSV/JSON tables, 16 plots, separate scientific and trading verdicts, and a longitudinal Markdown report. Daily status must reveal stopped streams, raw gaps, and disk growth.
6. Verify synthetic stop/resume and interval semantics, all phase offsets, delayed quote lookup, longer exact targets, frozen hash integrity and UTC boundaries; run the existing suite. Then perform a short live stop/resume, daily/final smoke analysis, inspect outputs and leave the real 7-day collection for the user.

Acceptance: no old run or raw part is overwritten; a restart produces a new session and visible downtime; a localized reconnect excludes nearby observations but does not globally reject a week; no Stage 2 observation trains the confirmatory Ridge or chooses its threshold/deciles; unavailable or too-short days are reported as insufficient rather than as evidence.
